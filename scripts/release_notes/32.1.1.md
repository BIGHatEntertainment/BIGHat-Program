# v32.1.1 (2026-10-13)

Source: PR #20 (merge commit 37879fe), tagged v32.1.1.

## Fixed
- **Local data could silently disappear.** `launcher.py` sets `MONTYDB_DATA_DIR` to the AppData folder, but `native/db_factory.py` only read `BIGHAT_DB_DIR`, which nothing sets. Packaged builds fell back to a folder beside the code (a per-launch temp dir). `db_factory.py` now honors `MONTYDB_DATA_DIR`.
- **Legal acceptance now persists.** New `backend/native/legal_router.py` stores an atomic `legal_acceptance.json` in the AppData folder, mounted at `/api/native/system/legal/*` through `system_router.py`. `LegalAcceptScreen.jsx` asks the backend and skips itself when the record matches both `LEGAL_VERSION` and the installed app version. It shows again on fresh install, after an update, or when the policies change. If the record cannot be saved the user sees a warning.

## Files
- backend/native/db_factory.py

## TESTED
- Acceptance logic only, with a FastAPI test client: fresh install, accept, relaunch, policy change, new app version. Atomic write leaves no temp files.

## NOT VERIFIED

- Updating over an existing Windows install (does the AppData folder, database and acceptance record survive; is the uninstall hook skipped).
- Existing installs whose data sits in the old fallback location are NOT migrated by this release.
- Other write paths (scores, locations, files) were not audited for the same problem.
