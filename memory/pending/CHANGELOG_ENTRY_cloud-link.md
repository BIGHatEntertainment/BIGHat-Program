## 2026-10-16 — v32.1.2: Cloud link (Admin > Integrations > BIG Hat Cloud)
- New: the Integrations tab has a "BIG Hat Cloud" card. It shows THIS computer's permanent 6-character code, a Copy button, a "Check link" button and the link state (Not linked yet / Waiting / Linked). The owner types the code into BIG Hat Cloud (Settings). The program always talks first, as the cloud app expects (POST /api/program/announce, then /api/program/claim-token).
- One code per computer, made once and never changed. A freelance host with 2 or 3 computers links each one to the same cloud account. The code is a label only; the product key is what proves the program and the account belong together.
- Storage: <AppData>/secure/cloud_link.json (installed program: %LOCALAPPDATA%\BIGHat\data\app\secure\). Written atomically. The cloud access key is stored ENCRYPTED with the same Fernet key file as the credential ledger (secure/ledger.key). The key is never returned by any API, never logged, never in the config or the database. A damaged file is kept as cloud_link.json.bad and never replaced by an empty one. In the installed app the backend refuses to store inside its own install folder.
- The cloud address comes from BIGHAT_CLOUD_BASE_URL or system config "cloud_base_url". While it is empty (the cloud app is not deployed yet) the card says so and nothing fails.
- New files: backend/native/cloud_link.py, cloud_link_router.py (mounted under /api/native/system/cloud-link/status and /check), backend/tests/test_cloud_link.py, backend/scripts/e2e_cloud_link.sh. Changed: native/system_router.py (mount), frontend lib/api.js, components/admin/IntegrationsTab.jsx.
